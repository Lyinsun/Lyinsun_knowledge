# Query

从索引快速定位答案，再按需进入专项、长期页面、事实源和 raw 证据。保持严格只读。

## 只读边界

- 不创建、修改、移动或删除知识库文件。
- 不创建操作日志，不自动调用写入型 Skill，不修复查询中发现的问题。
- 允许执行 Git 状态、搜索、读取、构建产物查看和授权范围内的只读查询。
- 如知识缺失，在答案中给出建议回填位置；只在后续显式写入任务中使用 `$add-wiki`、`$digest` 或 `$ingest`。

## 定位知识库

将包含 `_index/topic-map.md` 和 `workflows/knowledge-base-organization.md` 的最近祖先目录解析为 `KB_ROOT`。定位过程只读，不切分支、不拉取远程。

## 查询顺序

### 1. 全局索引

第一个读取 `$KB_ROOT/_index/topic-map.md`。根据分类摘要选择长期页面或专项 README，不先全量读取所有文档。

架构问题随后读取 `$KB_ROOT/architecture/README.md`，根据稳定边界选择 scope README，再进入 `architecture/<scope>/` 中的正文。与架构相关的未冻结设计、调研和交付状态仍从 scope README 链接到 `initiatives/`。

### 2. 专项本地索引

问题涉及当前需求、方案、调研、交付或状态时，先读 `initiatives/<name>/README.md`，再按其本地导航进入子页面。

### 3. 递归关键词搜索

索引不足时，递归搜索 `_index`、七个长期目录和 `initiatives`。使用同义词、接口名、事件名、路径和代码符号扩展搜索。

### 4. 事实源验证

- 按页面中的精确入口读取当前代码、配置、测试或数据。
- 文档与事实源冲突时以当前事实源为准，并在答案中说明差异。
- 运行时问题可使用授权的只读工具；记录环境、时间范围和查询边界。
- 不把一个测试环境、单个样本或历史观察外推为普遍事实。

### 5. Raw 追溯

只有需要核对原文、时间点或证据链时才读取 `raw/_manifest.md` 和对应快照。Raw 是证据，不自动等于当前稳定答案；先检查获取日期并与当前事实源交叉验证。

## 回答格式

先给结论，再给最短证据链：

1. 结论与适用范围。
2. 关键链路、状态或对比。
3. 知识页面、事实源和只读查询来源。
4. 未验证项、文档陈旧点或覆盖缺口。
5. 如有价值，给出建议回填位置，但不实际写入。

覆盖度可标为 `high`（多个独立来源一致）、`medium`（主要事实源支持但仍有局部缺口）或 `low`（只有单一来源、历史资料或合理推断）。引用尽量精确到文件和行号。
