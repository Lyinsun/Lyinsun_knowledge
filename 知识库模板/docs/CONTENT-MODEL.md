# 内容模型

## 笔记类型

| 类型 | 目录 | 解决的问题 | 必须关联 |
| --- | --- | --- | --- |
| 架构 | `architecture/` | 系统边界、组件和数据流是什么？ | 来源、相关服务 |
| 服务 | `services/` | 服务责任、入口和依赖是什么？ | 架构、接口、来源 |
| 模块 | `modules/` | 功能模块如何协作？ | 服务或接口 |
| 概念 | `concepts/` | 术语、实体、状态意味着什么？ | 领域来源 |
| 接口 | `interfaces/` | 调用、事件或数据契约是什么？ | 所有者、兼容性规则 |
| 流程 | `workflows/` | 如何开发、发布、运维或排障？ | 前置条件、恢复步骤 |
| 运维 | `operations/` | 如何安全执行常见操作？ | 风险、验证与回滚 |
| 决策 | `decisions/` | 为什么选择某种方案？ | 背景、替代方案、日期 |
| 来源 | `sources/` | 结论来自哪里、能否共享？ | 可见性、获取日期 |

## 最小元数据

除 README 外，权威工程笔记使用 YAML frontmatter，并至少包含：

```yaml
id: ARC-0001
title: Example Architecture
status: draft
owner: TEAM-A
last_reviewed: 2026-01-01
sources:
  - SRC-0001
```

`owner` 可以是匿名团队代号或角色，不能填写个人姓名、邮箱或联系方式。来源 ID 表示证据记录，不表示原文可公开。

## 规范与检查的边界

`kb.config.yaml` 是内容模型的描述性清单，帮助人和 Agent 理解默认目录、字段和维护模式；它不是动态规则引擎。若修改目录或必填字段约定，应在同一次变更中同步修改 `_templates/`、`AGENTS.md` 和检查器基线。

检查器默认是建议性诊断：它帮助 AI 发现断链、缺字段、隐私风险和来源关联遗漏，但不自动修改内容，也不替代来源所有者的判断。只有显式运行 `--strict` 时，才将发现的问题作为阻断条件。

## 证据等级

- `verified`：有可访问的权威来源或已验证实现证据。
- `inferred`：基于多个事实推断，应说明推断理由。
- `pending`：待验证，不能被引用为结论。
- `historical`：历史记录，需标注适用时间范围。
