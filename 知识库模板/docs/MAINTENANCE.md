# 知识库维护手册

## 新增一条知识

1. 从 `index/topic-map.md` 和全文检索确认没有重复主题。
2. 先创建或更新 `sources/` 中的来源记录；私密原文不入库。
3. 复制 `_templates/` 中对应文件，填写稳定 ID、所有者、状态、复审日期和来源。
4. 写出事实、推断、限制和适用范围。
5. 在来源与相关工程笔记的两端添加相对链接；参见 `docs/LINKING.md`。
6. 更新主题地图，并在关系复杂时更新关系地图。
7. 运行检查，将当前改动相关的提示作为排查清单；审阅差异后再提交。

## 修改或弃用一条知识

1. 先确认该笔记是否是主题地图中的权威入口。
2. 更新结论、状态、来源和 `last_reviewed`；失效内容使用 `deprecated`，不要静默删除历史决定。
3. 检查所有关联笔记，修正反向链接与来源的派生笔记列表。
4. 重新运行检查，确认与本次改动相关的提示已处理，再提交。

## 定期复审

- 每周或每次重要发布后：复审最近变动的架构、接口、流程和决策。
- 每月：检查 `review_after` 已到期的权威笔记，更新、弃用或标记为待验证。
- 每次对外分享前：检查 `docs/PRIVACY.md`，运行 `knowledge-lint`，并由内容所有者人工复核。

## 最小验证命令

```bash
python3 .agents/skills/knowledge-lint/scripts/check_knowledge_base.py --root .
git diff --check
```

如需将检查用作 CI 或发布门禁，再显式添加 `--strict`。
