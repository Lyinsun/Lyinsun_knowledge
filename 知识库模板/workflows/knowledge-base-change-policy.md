知识库将小范围内容写入与治理变更分开，并由采用本模板的仓库显式决定分支、评审和发布方式。

## 模板边界

- 本模板不预设默认分支、直推权限、代码托管平台、自动发布器或特定 Agent 运行时。
- 当前用户的明确授权和采用仓库的最近规则共同决定可以执行的写入、提交、推送、评审或发布动作。
- 当这些规则没有定义发布方式时，Agent 只完成已授权的本地文件修改，不自动扩展到外部写入。

## 最新基线准备

- `$query`、`$lint` 以及不修改仓库的分析、研究或计划任务保持只读，不切换分支、不拉取代码，也不以“同步基线”为由改变仓库状态。
- 已授权的修改型任务开始前，先运行 `git status -sb`，再从采用仓库的显式规则确定目标分支；未配置时使用仓库默认分支。
- checkout 干净时，使用 `git fetch origin <target-branch>`、`git switch <target-branch>` 和 `git merge --ff-only origin/<target-branch>` 将目标分支快进到远端最新状态，再记录分支、基线 commit 和同步结果。
- 存在未提交改动、分支分叉或 WorkTree 占用冲突时停止并报告，由用户决定如何处理；不得自动 stash、reset、clean、丢弃改动、强制切换分支或移除 WorkTree。
- 基线同步只保证任务基于最新代码开始，不额外授权文件修改、提交、推送、评审、发布或其他外部写入。

## 变更路由

| 变更类型 | 范围 | 默认处理 |
| --- | --- | --- |
| 只读操作 | 查询、lint、健康检查以及不改仓库的分析、研究或计划 | 不改文件、不创建操作日志、不切分支或拉取代码、不提交或发布 |
| 普通知识写入 | 小范围 wiki、专项、调研/方案文档、raw 快照和索引 | 准备最新基线后，在已授权 checkout 中按对应 Skill 完成，按仓库配置发布 |
| 已批准实施计划的执行 | 用户或上层任务明确指定已批准计划并要求实施 | 在冻结范围内执行实现、最小相关测试、失败修复和回归验证循环 |
| 仓内治理变更 | 只改变本仓内容与约定：目录调整、模板、Schema、Mermaid 配色、索引重组 | 与普通知识同路由，准备最新基线后按仓库配置提交发布，不额外要求独立分支与评审 |
| 跨边界治理变更 | 会影响本仓之外的行为：Agent 规则、Skill、验证脚本、发布自动化，以及批量移动或删除 | 准备最新基线后，优先使用独立分支和评审，遵循仓库级规则 |
| 已在进行的历史变更 | 规范生效前已存在的分支、WorkTree 或评审 | 继续创建时的流程，不为新规范迁移、合并或清理 |

Git 隔离方式不承担内容分类职责。普通知识仍然按 [`knowledge-base-organization.md`](knowledge-base-organization.md) 路由到长期知识、`initiatives/` 或 `raw/`。

### 仓内治理与跨边界治理的判定

治理变更曾一律要求独立分支和评审，但目录调整、模板、Schema、配色和索引重组只改变本仓内容，成本高于收益。分界线是**变更是否影响本仓之外的行为**：

| 判定 | 依据 |
| --- | --- |
| 仓内治理 | 影响范围限于本仓页面、目录与写作约定；错误可通过后续普通提交在本仓内修正，不改变任何外部系统或 Agent 的执行行为 |
| 跨边界治理 | Skill 与 Agent 规则会改变 Agent 在本仓之外的行为，且可能通过符号链接或安装步骤影响其他目录；发布自动化改变定时或 CI 行为；批量移动与删除有大范围断链风险，难以在单次评审外收敛 |

采用仓库若为仓内治理配置了直接提交路径，仍须遵守“写入和发布检查”，并只提交本次确认过的文件。判定不确定时按跨边界治理处理。

## 已批准实施计划的执行

只有用户或上层任务明确指出某个实施计划已经批准，并明确要求按该计划实施时，才启用本节。计划应已冻结目标、非目标、验收范围、写入边界和需要单独授权的不可逆动作；任务仅处于研究、设计、评审或待批准状态时，不得提前实施。

启用后按以下循环推进：

1. 实现当前计划范围内的最小完整改动，不顺带扩展未批准能力。
2. 运行最小相关测试或验证；失败时定位根因，修复实现并补充能锁住问题的必要回归检查。
3. 重跑受影响验证，并按仓库规则和改动风险决定是否扩大到 lint、构建或更完整的测试。
4. 审查最终 diff，如实记录通过、失败、跳过、环境不可用和未验证项；未执行或仅编译成功不得表述为测试通过。
5. 发现目标、范围、产品语义或不可逆边界变化时停止实施，先更新计划并重新获得确认。

`$query`、`$lint`、普通 `$add-wiki`、`$digest`、`$ingest`、小范围文档修订以及研究或方案编写继续遵循各自流程，不会因为存在专项或计划文档而自动进入本执行模式。

## 写入和发布检查

1. 修改型任务先按“最新基线准备”检查仓库顶层、当前分支、目标分支和未提交改动，不覆盖、暂存或提交其他任务的文件。
2. 只修改当前任务需要的页面、索引和 manifest，不顺手批量整理，也不创建逐次操作日志。
3. 检查 diff、frontmatter、链接、目录路由和敏感信息；至少运行 `git diff --check`。
4. 如已授权提交，只暂存和提交已复核的当前任务文件。
5. 推送、创建评审、合并和发布是独立的外部写入动作；只在当前授权和仓库规则明确允许时执行。
6. 输出如实说明本地修改、提交、远程推送、评审和发布的各自状态。

## 隐私与可移植性

- 模板文件使用占位符，不携带个人姓名、邮箱、本机绝对路径、内部仓库地址、组织专有机器人或业务名称。
- 示例不包含凭据、连接串、私有环境标识或未授权原文。
- 将模板用于具体仓库后，业务特定配置应留在该仓库，不回流到通用模板。
